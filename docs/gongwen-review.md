## 一、正向：模板 → 成文，参数是否真的继承

夹具：`make_blank_template.py` 生成的空白公文（版式按 GB/T 9704-2012 摆，内容全是占位符）。

| 项 | 模板登记值 | 产物实测值 | 国标要求 | 判定 |
|---|---|---|---|---|
| 页面 | 210×297mm | 210×297mm | A4 | ✅ |
| 天头/下白边 | 37 / 35mm | 37 / 35mm | 37 / 35mm | ✅ |
| 订口/右白边 | 28 / 26mm | 28 / 26mm | 28 / 26mm | ✅ |
| 版心 | 156×225mm | 156×225mm（推算） | 156×225mm | ✅ |
| 正文字号 | 16pt（3 号） | **16.0pt** | 16pt | ✅ |
| 行距 | 28pt（固定值） | **28.0pt** | 28pt | ✅ |
| 首行缩进 | 32pt = 2 字符 | `w:firstLine="640"`（32pt） | 2 字符 | ✅ |
| 标题字号 | 22pt（2 号） | **22.0pt** | 2 号 | ✅ |
| 中文字体 | 仿宋 / 方正小标宋简体 | `w:eastAsia` 一致 | 3 号仿宋 | ✅（字体是否安装取决于渲染机） |

XML 直查（不只看 Python 对象）：

```
<w:style w:styleId="Normal">
  <w:pPr><w:spacing w:lineRule="exact" w:line="560"/><w:ind w:firstLine="640"/></w:pPr>
  <w:rPr><w:rFonts w:ascii="仿宋" w:hAnsi="仿宋" w:eastAsia="仿宋"/><w:sz w:val="32"/></w:rPr>
</w:style>
```

`560 twips = 28pt`、`640 twips = 32pt`、`sz 32 = 16pt`——**固定行距与缩进是真写进样式的**，
不是靠段落逐段设置（那样一改模板就散）。

内容侧：标题、主送机关、正文 5 段（首段 + 4 段插入）、附件说明、成文日期、版记全部到位；
`{{印章位}}` 那行保持"只留位置"的说明文字，未生成任何图。

## 二、反向：四种"应该失败"的情况

| 制造的错误 | 期望 | 实测 |
|---|---|---|
| 只给标题，缺 5 个必填占位符 | 拒绝并列出缺哪些 | ✅ `缺少必填占位符：主送机关, 成文日期, 正文, 版记, 附件说明` |
| 把产物天头从 37mm 改成 20mm | `check` 退出 1 并指出差异 | ✅ `页边距 top: 模板 37.0mm → 产物 20.0mm` |
| 把模板文件替换成另一版 | `render` 拒绝（hash 变） | ✅ `模板文件与登记时不一致（hash 变了）` |
| `--allow-missing` 下留空 | 生成但**警告残留占位符** | ✅ `⚠ 仍有 N 个占位符未替换` |

第四条是复核时补的：原来的实现会生成一份**带 `{{姓名}}` 的公文**却显示成功——这是最典型的"看起来成功"。

## 三、复核中发现并修掉的三个缺陷

| # | 缺陷 | 影响 | 修法 |
|---|---|---|---|
| 1 | `measure_typography` 只读 `run.font.size` | **用段落样式排版的模板产物被量成"无字号"** —— 而样式排版恰恰是最规范的一类模板 | 四级回退：run → 字符样式 → 段落样式 → Normal |
| 2 | `line_spacing` 打印出 `355600` | `Length` 是 int 子类，被当成数值原样输出；人工核对时看不懂 | 新增 `_length_pt()`，按 `.pt` 换算 |
| 3 | 正文按 `\n` 拆段 | Markdown 的空行会变成空段落，公文的行距节奏被拉散 | 丢空行；只按非空行拆段 |

缺陷 1 是这次复核最值钱的一条：**如果不修，模板继承看起来"没生效"，人会以为工具没读字号**。

## 四、未解决的问题（如实记录）

1. **字体是否真的存在，工具无法确认**。`font_available()` 在没有 `fc-list` 的机器上返回 `None`（显示 `？`），
   不假装知道。macOS 默认没有仿宋，Word 会静默替换成宋体——**这一条只能靠"渲染机自检"兜住**，不能靠本工具保证。
2. **一个占位符被 Word 拆成多个 run 时**，替换会把整段重写（段内多样式丢失）。公文正文段落通常单一格式，
   影响小，但**不能声称无损**。
3. **`check` 只比对样式级参数**。如果有人在段落上单独覆盖行距（不走样式），`check` 抓不到。
4. **印章、红头、发文字号、版记**都不生成。模板里有就有，没有就没有；工具不会"补一个红头"。
5. **模板本身是否合规，工具不判断**。它只保证产物与模板同构——模板错了，产物错得更一致。

## 五、复核结论

- **L2（模板固化）达成**：版心、边距、字号、行距、缩进、标题层级、固定要素位置均被继承，且**可被量测复核**。
- **不构成"公文合规"**：不生成红头/版记/印章，不判断模板是否合规，不保证渲染机字体。
- **可以交给真实模板试用**：`template add` → `render` → `check` 三步都跑通，且失败路径都有明确报错。

> 下一步（L3 规则归纳）的前置条件：**拿到 ≥5 份真实单位模板**，抽出共性规则并逐条附样本与反例；
> 在拿到之前，不做任何"自动推断格式"的尝试——那会把确定性换成猜。
